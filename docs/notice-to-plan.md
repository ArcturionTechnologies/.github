# 🧩 From a confusing notice to a clear plan

**Conceptual walkthrough · fictional program · synthetic information**

This example shows a design direction for organizing administrative work. It does not query a model, connect to a portal, or submit anything.

## 1. The notice

> The fictional Community Workshop asks an applicant to renew their place by November 12, 2026. The applicant should provide a completed renewal form and proof of address. The notice does not say which documents qualify as proof or whether the deadline refers to receipt or submission.

## 2. Make the request legible

| Question | What the notice supports |
| --- | --- |
| What is being requested? | Renew a place in the Community Workshop. |
| What is the stated date? | November 12, 2026. |
| Which items are named? | Renewal form and proof of address. |
| What is unclear? | Accepted proof-of-address documents; receipt versus submission deadline. |
| Has anything been submitted? | No. |

The unanswered questions remain visible. The example does not invent the program's rules.

## 3. Choose one next step

**Prepare a question for the program office.**

Draft: “Could you confirm which documents you accept as proof of address, and whether November 12 is the submission date or the date the renewal must reach you?”

This is a draft for human review. It is not sent.

## 4. Create a resumable checklist

- [ ] Review the draft question.
- [ ] Choose how to contact the program office.
- [ ] Record the answer and its source.
- [ ] Locate an accepted proof document.
- [ ] Complete the renewal form.
- [ ] Review the final package before submission.
- [ ] Save the receipt if the person chooses to submit.

## 5. Preserve useful context

A minimal task note would contain the stated date, the evidence list, the unresolved questions, the current step, and the source of any later clarification.

Public examples should use fictional records. A real system would need appropriate handling for sensitive documents, access, retention, and deletion.

## What this illustrates

The pattern is **extract → clarify → organize → review → choose**. It turns an opaque task into a visible sequence while keeping uncertainty and human authority intact.

Whether this pattern helps real people, including people who get overwhelmed by complex processes, still needs to be tested.
